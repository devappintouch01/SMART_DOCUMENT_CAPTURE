# แผนงาน: บันทึกการใช้ AI และให้ superadmin เลือกโมเดล

สถานะ: วางแผนแล้ว ยังไม่เริ่มทำ (เริ่มสัปดาห์หน้า)

## เป้าหมาย

- ลดต้นทุนอ่านเอกสารจากประมาณ 2–3 บาทต่อใบ ให้ไม่เกิน **0.5 บาทต่อใบ (ราว $0.014)** โดยความแม่นยำไม่ตกจนใช้ไม่ได้
- รู้ว่าแต่ละใบใช้ AI ตัวไหน โมเดลอะไร ใช้เวลาเท่าไหร่ ต้นทุนเท่าไหร่
- superadmin เลือกโมเดลได้เองตอนอัปโหลด และเพิ่มลดรายการโมเดลได้เองโดยไม่ต้อง deploy

## สิ่งที่ตกลงแล้ว

1. **ตาราง `ai_calls`** หนึ่งแถวต่อการเรียก AI หนึ่งครั้ง (classify / extract / propose รวม retry) เก็บ provider, model, ประเภทงาน, เวลาเริ่มเรียก, ระยะเวลาตอบ (ms), input/output tokens, ต้นทุน, สถานะหรือข้อผิดพลาด เหตุผลที่ไม่ใส่คอลัมน์ใน `documents`: หนึ่งใบเรียก AI หลายครั้งและอาจต่างโมเดล
2. **เวลาตั้งแต่กดส่งจนเสร็จ** คำนวณจาก `uploaded_at` ถึงเวลาเสร็จ (รวมรอคิว) แยกจากเวลาตอบของ API ซึ่งเก็บใน `ai_calls`
3. **ข้อมูลเก่า**: ย้อนใส่ชื่อโมเดลแบบสันนิษฐาน (อ่านเอกสาร = claude-opus-5-5, จัดประเภท = claude-haiku-5-5) และติดป้ายว่าเป็นข้อมูลเก่า tokens และเวลาตอบเก่าย้อนไม่ได้ จะไม่เดาตัวเลข ข้อมูลใหม่เริ่มบันทึกจริงหลังปล่อย
4. **รายการโมเดลเป็น JSON** เก็บใน DB แก้ในหน้าตั้งค่าของ superadmin ตรวจรูปแบบก่อนบันทึก API key อยู่ใน env ไม่อยู่ใน JSON
5. **เลือกโมเดลตอนอัปโหลดแต่ละครั้ง** (ไม่ใช่ค่าทั้งระบบ) ใช้กับทุกไฟล์ในการอัปโหลดครั้งนั้น เก็บโมเดลที่เลือกไว้กับเอกสารแต่ละใบ เพื่อให้ retry ใช้โมเดลเดิม ผู้ใช้ปกติไม่เห็นตัวเลือก ใช้โมเดลที่ตั้งเป็นค่าเริ่มต้นในรายการ
6. **จัดประเภทอัตโนมัติ** คง Haiku ไว้เสมอ ไม่ขึ้นกับโมเดลที่เลือก
7. **อัตราแลกเปลี่ยน** กำหนดตายตัวใน config ที่ **35 บาทต่อ 1 USD** ใช้แปลงต้นทุนเป็นบาท ไม่ดึงตามวัน
8. **superadmin** เป็น login แยก ตั้งผ่าน `SUPERADMIN_USERNAME` / `SUPERADMIN_PASSWORD` ใน env ข้อมูล AI ซ่อนจากผู้ใช้ปกติที่ฝั่งเซิร์ฟเวอร์ (ไม่ใช่แค่ซ่อนบนหน้าจอ)

## ตัวเลือกโมเดลเริ่มต้น

| ชื่อที่แสดง | provider |
|---|---|
| (Anthropic) Claude Opus 5.5 | anthropic |
| (Anthropic) Claude Sonnet 5.5 | anthropic |
| (OpenRouter) DeepSeek V4.1 Flash | openrouter |
| (OpenRouter) Z.ai GLM 5.3 Flash | openrouter |

รูปแบบหนึ่งรายการใน JSON:

```json
{
  "id": "deepseek-flash",
  "label": "(OpenRouter) DeepSeek V4.1 Flash",
  "provider": "openrouter",
  "model": "<model id ตามที่ OpenRouter ใช้>",
  "params": { "temperature": 0, "max_tokens": 4000 },
  "pricePerMTok": { "input": 0, "output": 0 },
  "supportsPdf": false,
  "default": false
}
```

## ความเสี่ยงที่ต้องเช็กก่อนลงมือ

- DeepSeek และ GLM รุ่น Flash รับรูปหรือ PDF ได้จริงไหม รองรับการบังคับตอบเป็น JSON ตาม schema ไหม และราคาจริงเท่าไหร่ ให้ดูจากรายการของ OpenRouter ([vision-models](https://openrouter.ai/collections/vision-models)) ก่อน ถ้าตัวไหนรับแต่ข้อความ ต้องมีขั้น OCR ก่อน ซึ่งเพิ่มต้นทุน และอาจไม่ถึง 0.5 บาท
- บางโมเดลไม่รองรับ structured output ต้องสั่งใน prompt แล้วตรวจผลเอง
- เอกสารไทยที่อ่านยากอาจแม่นต่างกันมาก ต้องวัดด้วยเอกสารจริง ไม่ใช่เดา

## ลิงก์อ้างอิง

- รายการโมเดลที่อ่านภาพได้บน OpenRouter: https://openrouter.ai/collections/vision-models (ใช้ตรวจขั้นที่ 1)

## ความคืบหน้า

- ขั้น 2 (ตาราง `ai_calls` + บันทึกการเรียกของ Anthropic + คอลัมน์ `completed_at`): เสร็จแล้ว
- ขั้น 3 (superadmin login): เสร็จแล้ว ตั้ง `SUPERADMIN_USERNAME` / `SUPERADMIN_PASSWORD` ใน .env.local และบน Vercel เพื่อเปิดใช้
- ขั้น 4 (หน้า `/ai-usage` และแผงการเรียก AI ในหน้ารายละเอียดเอกสาร): เสร็จแล้ว

## ผลทดสอบเบื้องต้น (16 ต.ค. 2569)

ทดสอบด้วยสคริปต์ `npm run try:openrouter` กับเอกสารตัวอย่าง 6 ใบ (129 ช่อง) ใน `fixtures/demo` ซึ่งเป็นเอกสารสังเคราะห์ที่สะอาด ผลจึงเป็นขอบบนของความแม่นยำ ไม่ใช่ตัวแทนของเอกสารจริง

| โมเดล | ผ่าน | ต้นทุนเฉลี่ยต่อใบ (ขั้นอ่านเอกสารอย่างเดียว) |
|---|---|---|
| Claude Opus 5.5 (Anthropic ตรง) | 129/129 | 1.49 บาท |
| Claude Sonnet 5.5 (Anthropic ตรง) | 129/129 | ราว 0.74 บาท (ประเมินจากจำนวน token) |
| Claude Haiku 5.5 (Anthropic ตรง) | 129/129 | 0.05 บาท |
| DeepSeek V4.1 Flash (OpenRouter, PDF ผ่าน cloudflare-ai) | 84/129 | 0.035 บาท |
| DeepSeek V4.1 Flash (OpenRouter, PDF ผ่าน mistral-ocr) | 78/129 | 0.12 บาท |
| GLM 5.3 Flash (OpenRouter, PDF ผ่าน cloudflare-ai) | 64/129 | 0.038 บาท |

- DeepSeek และ GLM ผ่านแค่ 50–65% ถึงถูกมากก็ยังไม่คุ้ม และ PDF ต้องผ่านตัวแปลงของ OpenRouter ซึ่งทำให้ผลไม่เสถียร
- Haiku 5.5 ได้ครบทุกช่องในราคาต่ำกว่าเป้า 0.5 บาทเกือบ 10 เท่า และไม่ต้องเพิ่มผู้ให้บริการใหม่
- Claude ผ่าน OpenRouter ใช้ไม่ได้ในรูปแบบที่ทดสอบ (ขึ้น 404 เมื่อบังคับ structured output + temperature) จึงเทียบผ่านตัวอ่านเดิมแทน
- ยังไม่ได้ทดสอบกับเอกสารจริงที่ยาก (ถ่ายเอียง ลายมือ) ต้องทดสอบก่อนตัดสินใจเปลี่ยน

## ขั้นตอนที่เสนอ (เรียงตามลำดับ)

1. **ตรวจโมเดลที่จะใช้** ดูข้อมูลของ OpenRouter ว่ารับ PDF/รูป, structured output, ราคาเท่าไหร่ ผลลัพธ์: ตารางความสามารถของแต่ละโมเดล และตัดโมเดลที่ใช้ไม่ได้ออกก่อน
2. **ตาราง `ai_calls` + บันทึกการเรียกของ Anthropic** (migration, port, store, ใส่ในตัวอ่านเดิม) พร้อมย้อนใส่ชื่อโมเดลของข้อมูลเก่า ผลลัพธ์: เอกสารใหม่ทุกใบมีบันทึกครบ
3. **superadmin login** (env, บทบาทใน session, เช็กสิทธิ์ที่ฝั่งเซิร์ฟเวอร์) ผลลัพธ์: ผู้ใช้ปกติเข้าถึงข้อมูล AI ไม่ได้
4. **หน้าแสดงข้อมูล AI สำหรับ superadmin**: ในหน้ารายละเอียดเอกสารแต่ละใบ และหน้ารายงานสรุปต้นทุนรวม/เฉลี่ยต่อใบแยกตามโมเดล (ตกลงแล้วว่าทำทั้งสองส่วน)
5. **รายการโมเดลใน DB + หน้าตั้งค่า JSON** พร้อมตรวจรูปแบบ
6. **ตัวอ่านเอกสารสำหรับ OpenRouter** และตัวเลือกโมเดลตอนเรียกแต่ละครั้ง (เลิกเลือกจาก env ตอนเริ่มระบบ)
7. **dropdown เลือกโมเดลในหน้าอัปโหลด** (เฉพาะ superadmin) เก็บโมเดลที่เลือกกับเอกสาร และให้ retry ใช้โมเดลเดิม
8. **สคริปต์เทียบโมเดล** รันเอกสารตัวอย่าง 6 ใบที่มีเฉลยกับทุกโมเดล เทียบความแม่นยำ เวลา และต้นทุนต่อใบ ใช้ตัดสินใจเรื่อง 0.5 บาท

ขั้น 8 ทำคู่ขนานกับขั้น 6–7 ได้ และควรได้ผลก่อนตัดสินใจเปลี่ยนโมเดลเริ่มต้นจริง

## เรื่องที่ยังไม่ได้ตัดสินใจ

- ปุ่ม "อ่านใหม่ด้วยโมเดลอื่น" บนเอกสารที่มีอยู่ ทำภายหลังได้
